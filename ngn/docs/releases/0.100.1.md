# ngn v0.100.1 · durable Rust input queues

Patch on the first official monorepo `v0.100.0`. The Python core keeps its own
version; the Rust host owns all input admission, dispatch and control.

## Behavior and controls

- Enter accepts input while working; pending inputs execute in FIFO order after
  the current run and its descendants finish. Up to 32 pending per session and
  256 per host, within the existing eight-root/64-run host capacities.
- TUI **F6** inspects pending inputs; **Ctrl+P** pauses/resumes, **Ctrl+X** removes
  the selected pending input, **Ctrl+K** clears pending inputs and pauses. `/queue`,
  `/queue pause`, `/queue resume`, and `/queue clear` provide command equivalents.
- Browser controls match the TUI. `GET /api/sessions/{id}/queue` returns the FIFO;
  `POST` accepts only `{"action":"pause|resume|clear"}` (one literal action).
  The existing run-submission endpoint now durably queues busy inputs. Run cancel
  also accepts pending run IDs. Child sessions cannot admit/control root queues.
- Pausing or clearing pending work does not cancel active work. Stop cancels the
  root/subtree **and pauses** its queue. Failure, shutdown and restart pause it too.
  Removing one pending input does not affect other inputs, active runs or siblings.
- Explicit resume dispatches only unstarted inputs. Claimed/interrupted runs are
  not automatically retried. No exactly-once guarantee is made for external side
  effects across a crash; completed actions are not rolled back or replayed.
- Submission UUIDs keep their identity after dispatch/cancellation. Retries with
  different text fail; retries cannot upgrade stored approval mode. Every modifying
  tool still requires its own exact run/call approval when the input executes.
- Headless `run --json` remains immediate and fails instead of bypassing pending
  or paused inputs. FIFO is not active-generation steering or a subagent follow-up API.

## Upgrade

Back up important Rust workspace state **with the host stopped**. Schema **2→3**
adds durable queues and permits session-scoped queue journal records with an empty
`run_id`; these are not child or model events. Existing event cursors and run
identities are retained. Old 0.100.0 binaries reject schema 3; restore the backup
to downgrade. Legacy Python state and opaque runtime databases remain untouched.
Agent Runtime Protocol v1 and exact tool binding remain unchanged.

## Acceptance scope

Core tests cover FIFO, concurrent idempotency, policy retention, removal/clear,
Stop/failure, capacity admission, isolated sessions, crash recovery and schema
migration. Browser fixtures reject stale queue state and preserve newer drafts.
Real fixture-model HTTP/WebSocket tests cover queued reads/writes, per-turn
approvals, controls on empty sessions, Stop/clear, crash recovery and explicit
resume. Real PTYs exercise F6, busy submission, remove/resume/clear, Stop, reopening
a durable paused queue and terminal restoration. The release gate runs these
against the optimized binary and packaged adapter wheel.

### Recorded local acceptance — 2026-11-17

- Root pre-commit: all gates passed, including **38 Rust, 4 adapter, 8 packaging
  guard and 11 browser tests** (61 total). Ten additional core repetitions passed
  **250 test executions**.
- A fresh virtual environment installed the built 0.100.1 adapter wheel and
  published PyPI `nagents 0.28.5`, without editable imports. All eight actual
  CLI/HTTP/WebSocket/PTY acceptance suites passed with the optimized binary.
- Checksums, exact source-commit binding, source/wheel provenance and an extracted
  Python-free install passed verification. Negative tests reject mismatched tags,
  foreign commits/core versions, corrupt assets, missing manifests, unsafe paths,
  unsupported platforms and dirty packaging candidates.
- A real Chromium flow passed paused/busy submission, FIFO inspection, selected
  removal, clear without cancelling the active root, Stop, explicit resume and
  completion. Pause also propagated to another browser tab via session-scoped
  WebSocket events, without duplicating queued/cancelled user turns.

Remote CI and tag publication remain separate release gates; these local results
are not a claim that a draft branch is already a published release.

Steering, queue editing/reordering, attachments, follow-ups, profiles/settings,
original UI parity, MCP/skills, channels, A2A and voice remain incomplete. Local
model fixtures are not paid-provider validation or cross-browser visual QA.
