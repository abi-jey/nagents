# ngn 0.100.1 · Rust-supervised subagents

> Historical **local-only prototype** notes. Its features and fixes are included
> in the first official monorepo `v0.100.0`; this is not an official published
> 0.100.1 release. Original standalone tags/artifacts remain untouched.

Patch release on `stabilize/0.100.1-subagents`, following the preserved `v0.100.0`
baseline. Rust—not the Python harness—owns child admission and processes.

## What's usable

- `to_agent` runs a child with an isolated session; foreground waits for its final
  public text, while `background: true` returns a handle for `agent_wait`.
- `agent_status`/`agent_wait`/`agent_cancel` require the exact immediate owning run.
- Default shared root limits: depth 2, three concurrent subagents, eight executions,
  300-second child deadline. Limits are explicit JSON configuration, not mutable
  model instructions. Saturation is rejected rather than queued.
- Child permissions can only tighten; approval mode, backend and provider are
  inherited. A child cannot reopen its session as a less restricted root.
- Parent cancellation cascades through descendants. Parent termination follows
  child cleanup. Finishing with active background work fails closed and cancels it.
- **F5** opens TUI agents, **Enter** inspects, **Ctrl+X** cancels the selected child.
  The browser provides the same catalog/inspection/cancel controls. Child approvals
  appear in the owning root UI but remain bound to the actual child run/call.
- Child text streams stay in child conversations. Root lifecycle notices contain
  host-owned metadata, not child reasoning or forged root assistant messages.

## Important adapter fix

Protocol v1 uses `error: ""` for a successful tool result; nagents expects Python
`None`. The adapter now translates that correctly. Previously the UI could show
success while the model's saved tool message read `Error:`. The integration fixture
now parses the model's actual tool messages to drive background result delivery.
This corrects new results; opaque historical runtime messages are not rewritten
or used as authorization to replay previously executed tools.

## Upgrade and compatibility

Agent Runtime Protocol **v1 remains unchanged**; subagent tools use its existing
schema catalog and tool-request/result binding. Client lifecycle events gain
host-owned `task_started`, `task_updated`, and `task_finished` variants.

The private Rust host database upgrades from schema **1 to 2**, adding task topology
and recovery metadata. Existing roots, event journals and titles are retained.
The runtime-owned nagents database is not opened or migrated by Rust. Stop the host
and back up its workspace state before upgrading important data. An old 0.100.0
binary refuses schema 2; restore a pre-upgrade backup to downgrade.

Restart interrupts saved child runs and records their lifecycle without replaying
model requests or tools. It does not resume work or claim exactly-once side effects.

## Regression coverage

- Core: foreground delivery, direct-parent authorization, read-only ceilings,
  nested ancestry, depth/concurrency/execution accounting, simultaneous admission,
  independent roots, cancellation/deadlines, unjoined cleanup and restart migration.
- TUI: child inspection and actual-child approval binding; real PTY interaction
  opens F5, inspects a child, cancels it with Ctrl+X, keeps the parent alive and
  verifies clean exit/terminal restoration.
- HTTP/WebSocket: real nagents child processes, two background results delivered to
  the parent model, child-specific approvals, denied forged read-only writes,
  independent child replay, cross-conversation stream isolation, child-only/root
  cancellation and rejection of child-session promotion to root.
- Browser logic: task inspection/cancel identity, child approval attribution and
  existing replay/idempotency/stale-state regressions (DOM fixture, not visual QA).

## Remaining scope

No claim of complete legacy parity: profiles/settings, input queues and steering,
child follow-ups, automatic model-boundary notifications, original React/Textual
UX, MCP/skills, channels, A2A and voice remain on the migration checklist. The
initial validated platform is Linux; model tests use local fixtures, not paid
provider accounts. Releases remain local until a remote destination is configured.
