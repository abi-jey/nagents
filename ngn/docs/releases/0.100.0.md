# ngn v0.100.0 · first official Rust release

Rust harness, Ratatui TUI and loopback web host, released from **abi-jey/nagents**.
The Python `nagents` core remains in the same repository, with its own version.
This official release rolls up the previously tested standalone local 0.100.0 and
0.100.1 prototypes, including subagent supervision and corrected successful tool
results. Those local tags/artifacts were not published or overwritten.

## Install and run — Linux x86_64

Download `ngn-v0.100.0-linux-x86_64.tar.gz` and `SHA256SUMS` from this release.
Verify the archive's hash against its line in `SHA256SUMS`, then:

```sh
mkdir ngn-rust-0.100.0
tar -xzf ngn-v0.100.0-linux-x86_64.tar.gz -C ngn-rust-0.100.0
./ngn-rust-0.100.0/ngn --version
./ngn-rust-0.100.0/ngn --demo -C /path/to/project
./ngn-rust-0.100.0/ngn --demo -C /path/to/project serve
```

Use the exact printed loopback URL. Use the binary's explicit path: installing
the Python library still provides the legacy Python `ngn` console script.
Do not replace an existing environment or installed client implicitly.

The demo requires neither Python nor provider credentials. For live agents,
create a **new** Python virtual environment, install the attached `ngn_nagents`
wheel (which depends on the reusable `nagents` library), and configure its absolute
interpreter/provider using `config.example.json`. See the [Rust README](../../README.md).
Keys stay in referenced environment variables, never in JSON, URLs or arguments.

## Included

- Rust-owned file/shell tools, bounded validation and exact per-call approvals;
  noninteractive and read-only runs fail closed.
- Durable sessions/events, idempotent submission, cursor-based WebSocket replay,
  native terminal interaction and authenticated same-origin HTTP controls.
- Rust-owned foreground/background subagents, isolated sessions, immutable ancestry,
  shared limits, child deadlines, child inspection and subtree cancellation.
- Public-library Python adapter through Agent Runtime Protocol v1, without importing
  Python harness, TUI, web server, filesystem tools or arbitrary plugins.
- Correct empty-wire-error to Python `None` conversion for successful tool results.
- Separate Rust CI/release pipeline, packaged-wheel/optimized-binary smoke tests,
  extracted-install verification, SHA-256 checksums and exact-commit provenance.

## Compatibility and limits

The host uses private schema 2 and never reads/migrates legacy Python configuration
or databases implicitly. Back up important workspace state with the host stopped.
Restart marks interrupted work; it never replays tools or automatically retries it.
The Linux archive uses Ubuntu 24.04's system C runtime (glibc); it is not static or
a validated macOS/Windows build. The source archive contains both Python and Rust.

This is **not complete legacy parity**. Input queues/steering, follow-ups,
profiles/settings, original UI parity, MCP/skills, OAuth, channels, A2A and voice
remain in progress. Paid-provider accounts and cross-browser visual behavior have
not been validated. See the [migration inventory](../migration.md).

## Acceptance

Release publication is gated on root pre-commit (including formatting, strict
Clippy, Rust/adapter/browser tests), six actual CLI/HTTP/WebSocket/PTY fixture
suites using the optimized binary and built adapter wheel, and verification of
the extracted install without Python or shell executables on PATH. CI run results
and the exact source commit are attached to the release through its manifest.
