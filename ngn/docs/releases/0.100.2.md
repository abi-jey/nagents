# ngn v0.100.2 · development launcher and native tool presentation

**Development candidate, not yet released.** It follows the immutable official
0.100.0 baseline and the separately gated 0.100.1 FIFO patch. Python retains its
independent version and reusable provider/agent implementation.

## Changes

- Preserve the 46-file original local working set on a pushed branch before any
  checkout cleanup. Reconcile it with reviewed main rather than reintroducing older
  provider and cancellation code. Keep all legacy features in the monorepo.
- `./ngn/dev` rebuilds the optimized, locked binary and Python wheels, installs a
  new runtime environment, archives/extracts the binary and launches its explicit
  installed path. Uncommitted source is supported; changes during a build reject
  the mixed candidate. `--test` executes real installed CLI/HTTP/WebSocket/PTY checks.
- Keep development configuration, state and environments separate from installed
  and legacy state. Explicit provider configuration is retained while the runner
  is rebound to the staged environment. No config means the offline Rust demo.
- Rust owns each tool's active clock. Its approval waiting is excluded on allowed
  and denied calls; durable call-bound snapshots show that waiting state to UIs.
- Native TUI and browser tool summaries retain recognized targets and format bounded
  compact durations. Raw arguments/results stay inspectable; arbitrary custom
  fields are not promoted into summaries. Skill-name formatting does not imply
  that a skill runtime has been implemented.
- Touch browser Return edits the draft rather than sending. Explicit Send/Queue
  and Stop retain focus; mobile conversation creation/selection and bounded
  approval previews keep controls reachable at short touch viewport sizes.

Runtime protocol v1 and host schema 3 are unchanged for these changes. The original
v0.100.0 tag/assets are not replaced. The development manifest is not an official
release manifest or a claim that third-party dependency resolution is reproducible.

## Evidence and gates

- The launcher's first pushed commit passed all eight installed acceptance suites
  in a separate worktree containing an uncommitted packaging marker. It installed
  non-editable local core/adapter wheels and ran the extracted optimized binary.
- The native timing/presentation changes passed **42 Rust, 4 adapter, 14 script and
  16 browser regressions**, strict Clippy and root pre-commit. An installed dirty
  candidate additionally passed all eight CLI/HTTP/WebSocket/PTY suites and real
  Chromium desktop/touch tests (including actual child approvals and native writes).
  Official release
  packaging and current-head real UI/provider acceptance remain separate gates.
- The released baseline's complete local Python suite passed **6,345 tests with
  10 skips**, after choosing a private test root accepted by guarded stores.

Codex/device login, profiles/settings, active-run steering, nested skills/MCP,
managed jobs, original UI parity, attachments, channels/A2A, voice, and remote
Kubernetes deployment remain explicit migration work. Do not replace an existing
fully featured deployment with this limited host solely because its binary builds.
