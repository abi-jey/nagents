# ngn v0.100.2 · development launcher, native authentication and safe steering

**Development candidate, not yet released.** It follows the immutable official
0.100.0 baseline and the separately gated 0.100.1 FIFO patch. Python retains its
independent version and reusable provider/agent implementation.

## Changes

- Preserve the 46-file original local working set on a pushed branch before any
  checkout cleanup. Reconcile it with reviewed main rather than reintroducing older
  provider and cancellation code. Keep all legacy features in the monorepo.
- `./ngn/dev` rebuilds the optimized, locked binary and Python wheels, installs a
  new runtime environment, archives/extracts the binary and launches its explicit
  installed path. Uncommitted source is supported; changes during a build reject
  the mixed candidate. `--test` executes real installed CLI/HTTP/WebSocket/PTY checks.
- Keep development configuration, state and environments separate from installed
  and legacy state. Explicit provider configuration is retained while the runner
  is rebound to the staged environment. No config means the offline Rust demo.
- Rust owns each tool's active clock. Its approval waiting is excluded on allowed
  and denied calls; durable call-bound snapshots show that waiting state to UIs.
- Native TUI and browser tool summaries retain recognized targets and format bounded
  compact durations. Raw arguments/results stay inspectable; arbitrary custom
  fields are not promoted into summaries. Skill-name formatting does not imply
  that a skill runtime has been implemented.
- Touch browser Return edits the draft rather than sending. Explicit Send/Queue
  and Stop retain focus; mobile conversation creation/selection and bounded
  approval previews keep controls reachable at short touch viewport sizes.
- Native discovery uses bounded workspace `.gitignore` files with nested origin,
  anchoring, negation and excluded-ancestor semantics. Protected paths cannot be
  unignored. Explicit-file search uses the same rules; no instruction payload or
  global Git configuration is implicitly loaded.
- Reusable Python device authentication/guarded storage no longer require a
  harness/UI import. Cooperative POSIX refresh serialization, logout revisions and
  durable interrupted-attempt markers prevent unsafe renewable-token replay.
- Explicit development ChatGPT configuration and native CLI login/status/logout
  use that core API through a capability-gated credentials callback and bounded
  private frames. Identity writers exclude live hosts and orphaned runtimes.
  No credential values, Codex cache discovery or API-key fallback cross the boundary.
  Official subscription release requires publication of the new core API first.
- Explicit active-root steering uses separate bounded receipts, a two-sided
  optional protocol-v1 handshake and complete persisted tool-batch/final boundaries.
  Offered-but-unconfirmed inputs become uncertain, pending inputs undelivered;
  neither is automatically replayed or converted into next-run FIFO.
- The browser's separate Steer active turn and TUI `/steer TEXT`/F7 expose exact-run
  steering and durable receipts. Enter/Send remains next-run FIFO. Reconnect uses
  snapshots/events, not automatic POST replay; failure retains exact retry identity.
- Development and release-shaped archives include both checked-in API-key and
  ChatGPT example configurations, never local configuration or authentication state.
- The launcher creates each missing cache ancestor privately, independent of shell
  umask, without repairing existing unsafe paths. `--test` additionally proves a
  Python-free offline/read-only launch in the real cache ancestry, using only
  candidate-owned workspace/state rather than an operator's data directory.

Runtime protocol stays v1 with independently negotiated auth/steering extensions.
Host state upgrades from schema 3 to **4**, preserving queues/cursors. Stop the host
and back up important state first. Older binaries refuse schema 4; downgrade using
a separate state directory or that backup, never by editing `user_version`.
Runtime/legacy databases are not migrated. The original v0.100.0 tag/assets are not
replaced. The development manifest is not an official release manifest or a claim
that third-party dependency resolution is reproducible.

## Evidence and gates

- The launcher's first pushed commit passed all eight installed acceptance suites
  in a separate worktree containing an uncommitted packaging marker. It installed
  non-editable local core/adapter wheels and ran the extracted optimized binary.
- The final integrated source candidate `2c9f24e` passed **6,397 Python tests with
  10 skips**, **89 Rust, 26 adapter (zero skips), 30 script and 28 browser regressions**,
  strict Clippy and all 17 root pre-commit hooks. Relevant Rust/adapter/script
  checks passed under both shell umasks 0002 and 0022 without weakening storage
  ownership checks. The clean installed candidate passed all eight
  CLI/HTTP/WebSocket/PTY suites, real Chromium desktop/touch checks, native-auth
  tests, browser/TUI steering, legacy-runtime compatibility and crash/no-replay checks.
  Fresh default-cache offline launches and local archive provenance/examples passed.
  Exact-head hosted/platform CI and official publication remain separate gates;
  successful Linux results do not waive Windows or macOS failures.
- With a separately authorized fresh login, that installed candidate also passed
  bounded real `gpt-5.6-terra` questions in a PTY TUI and Chromium: independent
  native file reads returned distinct expected fixture contents. Hosts/runners
  exited cleanly and terminal settings were restored. Schema-4 state used a new
  workspace; the earlier schema-3 workspace was unchanged. A live steering attempt
  missed its admission window and submitted nothing, so live steering delivery
  is **not** claimed. No provider/auth fallback or charged retry loop was used.
- The released baseline's complete local Python suite passed **6,345 tests with
  10 skips**, after choosing a private test root accepted by guarded stores.

Broader live-provider/refresh coverage, live steering delivery, browser login,
profiles/settings, model-generation interrupts, nested skills/MCP, managed jobs,
original UI parity, attachments, channels/A2A, voice, and remote Kubernetes deployment
remain explicit migration work. Do not replace an existing fully featured
deployment with this limited host solely because its binary builds.
